# Управление несколькими AmneziaWG-серверами

## 1. Базовая модель

Локальный каталог `amnezia` на Windows-ноутбуке — единственный источник истины. Все VPS равноправны, не синхронизируются друг с другом и считаются заменяемыми экземплярами одной конфигурации.

Общие для всех VPS: серверная пара ключей, VPN-сети, AWG-параметры и набор клиентов. Индивидуальные для VPS: публичный IP и UDP-порт из `servers.txt`.

Компрометация одного VPS раскрывает общую серверную пару ключей и является принятым компромиссом этой схемы ради простого переключения клиента только сменой `Endpoint`.

## 2. Локальные данные

```text
config/server.env          общие сети, DNS, серверные ключи и AWG-параметры
config/awg0.conf.template  серверный шаблон и все peer
clients/*.conf             один постоянный профиль на физическое устройство
clients/generated/         производные профили для других VPS
servers.txt                Name;IP;Port;Enabled
logs/amnezia.log           общий журнал
```

Секреты не должны попадать в git, облачную синхронизацию или незашифрованный резервный архив. Для ноутбука требуется шифрование диска и зашифрованный backup.

### Первая настройка проекта

В git лежат только примеры; рабочие файлы перечислены в `.gitignore`:

- `servers.txt.example` → скопировать в `servers.txt` и указать свои VPS.
- `config/awg0.conf.template.example` → скопировать в `config/awg0.conf.template` (peer добавляет `add-client.ps1`).
- `config/server.env.example` — только образец формата. Рабочий `config/server.env` создаёт `generate-server-env.ps1` (ключи и AWG-параметры в примере — нули и пустые значения, копировать его как есть нельзя).

## 3. Скрипты

- `generate-server-env.ps1` — создаёт новый `server.env`: новую серверную пару ключей и случайные AWG-параметры. При `RandomTrailers=on` используется `S1=S2=S3=S4`.
- `add-client.ps1` — создаёт клиента, его ключи/PSK, постоянный `clients/CLIENT.conf` и peer в шаблоне.
- `remove-client.ps1` — удаляет клиента из локального источника истины.
- `make-client-config.ps1` — создаёт производный профиль клиента для выбранного VPS, меняя только `Endpoint`.
- `sync-servers.ps1` — главный оркестратор: проверяет состояние VPS, выполняет первоначальную настройку/ремонт и синхронизацию.

`upgrade.sh`, `bootstrap.sh`, `secure.sh` выполняют соответственно обновление ОС, установку/настройку AmneziaWG и security hardening.

## 4. Новый VPS

1. Создать Ubuntu 24.04 VPS и установить SSH public key для `root`.
2. Выполнить первый SSH-вход вручную и сверить fingerprint host key с данными провайдера. Автоматизация использует `StrictHostKeyChecking=yes`.
3. Добавить VPS в `servers.txt` с уникальным UDP-портом.
4. Выполнить `sync-servers.ps1 SERVER`.
5. Скрипт различает состояния:
   - `NEW` — сначала `upgrade.sh`; перед первым bootstrap при отсутствии клиентов предлагает создать первого клиента. Отказ не отменяет выполненный upgrade: bootstrap получает статус `PENDING`;
   - `DEGRADED` — предлагает восстановительный `bootstrap.sh` без `dist-upgrade`;
   - `READY` — обычная синхронизация.
6. После bootstrap пользователь проверяет VPN; только затем запускается `secure.sh`.

## 5. Синхронизация

Локальные клиентские профили один раз за запуск приводятся к `server.env`. Пустой список peer является допустимым состоянием для `READY`/`DEGRADED` и позволяет, в частности, синхронизировать удаление последнего клиента. Для каждого VPS формируется индивидуальный `awg0.conf` с его `ListenPort`.

Конфигурация передаётся во временный `/root/.amnezia-sync` и удаляется после операции. При изменении `awg0.conf` интерфейс `awg0` полностью перезапускается, чтобы гарантированно применить ключ, порт и все AWG-параметры.

Если меняется AWG-порт и UFW уже активен, новый UDP-порт открывается до перезапуска, а старый закрывается только после успешной проверки. При ошибке выполняется rollback.

Ошибка одного VPS не прекращает обработку остальных. Все действия записываются в `logs/amnezia.log`; секреты в журнал не выводятся.

## 6. Клиенты

Каждое физическое устройство имеет собственные ключи, PSK и внутренние адреса. Один и тот же peer присутствует на всех VPS.

Постоянно хранится один `clients/CLIENT.conf`. Производный профиль для другого VPS хранится как `clients/generated/CLIENT/SERVER.conf` и отличается только `Endpoint = IP:PORT`.

После `add-client.ps1` или `remove-client.ps1` выполняется `sync-servers.ps1 all`.

## 7. Обновления и эксплуатация

`upgrade.sh` устанавливает headers текущего ядра, `linux-headers-generic` и DKMS. Проверка состояния контролирует headers и DKMS-модуль AmneziaWG для наиболее нового установленного ядра.

IPv6 реализован через ULA + NAT66. Если на VPS нет рабочего глобального IPv6-маршрута, bootstrap выводит предупреждение: IPv6 через такой VPS может не работать.

Не запускать управляющие скрипты параллельно. После ручного `ufw reload` нужно проверить/перезапустить `awg-iptables.service`.

- Короткая SSH-проверка имеет hard timeout 15 секунд; рабочие SSH/SCP-сессии используют keepalive и не ограничивают длительность upgrade/bootstrap.
